A browser for building, not browsing

Every viewport, at once.

Breakpoint renders one URL at six sizes side by side on a canvas that scrolls, clicks and navigates in sync. One console for all of them. Driven from the command line, so your agent works the same panes you are watching.

Synced input

Scroll one pane. They all move.

Scroll position, clicks, hovers, form input and navigation propagate across every pane, mapped by proportional offset rather than absolute pixels, so a 390px column and a 1920px grid stay on the same section.

Hold ⌥ to drive one pane alone when a layout only breaks in one place.

One console

Six pages, one stream, labelled.

Every pane logs into the same console, tagged with the colour it carries everywhere else. When the same message arrives from several panes it collapses into one row with several badges, so a universal warning takes one line and a viewport-specific error stands out.

Holds 2,000 entries a second without dropping frames.

A pane's colour means the same thing everywhere.

Ten hues at one lightness and one chroma — quiet enough to sit over any page, distinct enough to tell six panes apart at a glance. The same colour tags the header, the console row, the layout finding, and the border baked into composite screenshots.

CLI & agents

Your agent drives the same panes.

Everything in the UI is a command. A coding agent adds panes, navigates, reads the console as JSON and takes screenshots — in the window you are already watching, not a headless copy of it.

❯ breakpoint pane add mobile --url /checkout
❯ breakpoint console --level error --json
❯ breakpoint shot --all --out shots/

The canvas

Three to ten panes, 25% to 100%.

Horizontal to compare neighbours, Fit to see the whole set, Focus to work in one at full size with the rest as a strip. Panes are real renderers, not iframes — service workers, storage and devtools all behave.
